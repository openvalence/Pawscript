How it was made (2026-11-18)
  copy %USERPROFILE%\AppData\Roaming\uv\python\cpython-3.12.12-windows-x86_64-none to <build>\python
  uv export --frozen --no-hashes --no-emit-project --extra sam2 --extra describe --extra tapnext --group dev  (patched lock)
  SAM2_BUILD_CUDA=0 uv pip install -p <build>\python\python.exe --break-system-packages --no-deps -r requirements.txt
      --index-url https://pypi.org/simple --extra-index-url https://download.pytorch.org/whl/cu130 --index-strategy unsafe-best-match
  pawtrack.pth as above; ffmpeg.exe / ffprobe.exe taken from runtime-2026-11-17.zip (tar -xf ... ffmpeg.exe ffprobe.exe)
  tar --format zip -c -f runtime-2026-11-18.zip -C <build> python ffmpeg.exe ffprobe.exe -C <dir with runtime.stamp> runtime.stamp
  (deflate level 9 instead of the default saves 0.1 %: the CUDA DLLs barely compress)

Shipped (paw-7yed, 2026-11-18)
  The owner's call: this is the only runtime Pawscript ships; no "legacy cards" download (GTX 9xx / 10xx owners are not
  a concern). trackers/uv.lock carries the cu130 index since commit 12ccaec. build-nas.ps1 takes it by the pinned name
  in $RuntimeArchive (no longer "the newest by name", which picked runtime-public-2026-11-18.zip) and stops when this
  record's runtime.stamp or the zip's own differs from the lock's torch build.

Release assets
  GitHub caps an asset at 2 GiB; this archive is 2.13 GiB. build-nas.ps1 cuts it into runtime.zip.001 (2,000,000,000
  bytes) and runtime.zip.002 (287,006,433 bytes) beside the exe, listed with size and sha256 in parts.txt; the exe's
  first start joins them in place into runtime.zip (portable.rs, dev/patches/paw-7yed-runtime-parts.patch until applied)
  and then unpacks it as before. The two TAPNext++ checkpoints (2,532,282,370 / 2,532,283,010 bytes) go the same way.

docs/guide/cotracker.md's opt-in was checked on the cu126 public runtime, which still had matplotlib; this one has not.
